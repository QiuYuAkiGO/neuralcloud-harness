2026-11-21 起草，供共同评审。每个议题分别记录项目方提出的修订、供讨论的方案和仍待决定的问题。后续讨论可在对应议题下补充反例、替代方案或已采纳的决定。

## 修订一　跨会话更正与 Worker 记忆读取登记

### 项目方提出的设计

为每个 Worker 进程绑定一份记忆读取注册表。Worker 调用相关记忆时，把本次调用读取了哪些记录登记进去。某条记忆被更正后，系统可以按记录找到读过它的下游 Worker，及时通知对应进程。即使两个 Worker 分属不同会话，也能知道谁可能仍在使用旧信息。

目前开放的是通知到达之后的行为。正在组织回复的 Worker 需要保持会话连续性，准备按旧信息采取行动的 Worker 又有时效要求。项目方希望避免每次更正都打断正在进行的模型推理。原提案已提出按依赖刷新，本次修订进一步明确了登记时机和注册表与 Worker 进程的关系。[认知架构提案第 4 节](master-worker-cognitive-architecture-20261117.md)

### 候选方案　及时通知进程，在使用旧信息前更新

建议由运行时登记实际交给 Worker 的记录标识（`record_id`）和读到的版本（`revision`），覆盖主动读取和自动注入。更正到达时，运行时立即把受影响的记录标为待复核，允许当前生成自然结束。这样可以分别处理“进程已收到通知”和“模型已使用更正后的依据”两个时点。

| Worker 所在时点 | 建议的处理方式 |
| --- | --- |
| 正在起草回复或处理内部步骤 | 暂存更正，无关步骤继续。多次更正同一记录时，保留变更历史，给模型的更新可合并为一次。 |
| 即将构造下一轮模型输入 | 按当前会话的可见范围重读待复核记录，在原会话末尾追加一条由运行时标明来源的更正说明，保留此前对话。来源已撤回时，说明哪项依据已失效。 |
| 本轮准备发送依赖该记录的回复、执行工具或提交派生摘要 | 向记忆服务核对所依赖记录的当前版本和有效状态，避免通知尚在路上时放行已过期的输出。发现冲突就暂缓这项输出，让 Worker 依据最新材料重做相关部分。派生摘要的来源版本需要在写入事务内核对。 |

例如，B 根据“周五 15 时开会”起草提醒，期间 A 把会议改到周六 10 时。按这个候选方案，B 可以写完草稿。若下一步就是发送，运行时先暂缓旧提醒。B 下一轮收到记忆工具的返回“根据用户的改期消息，会议时间已从周五 15 时改为周六 10 时。”任务指令“请重新核对待发提醒”另行给出。若渠道已经确认送达，则保留原回执，另行处理对外更正。

注册表还需识别**依据失效但版本号未变**的情形。现有记忆服务在来源更正后，可将此前生成的摘要标为 `SOURCE_CHANGED`，摘要自身的版本号仍保持原值。初版评估也复现了另一种顺序，即旧摘要可能在更正后才提交。这两种情况分别检验通知消费和提交时复核。[初版可行性评估第 4 页](NeuralCloud重构可行性评估报告-初版-20261121.pdf#page=4) · [记忆存储实现](../../src/neuralcloud/storage.py)

### 留给下一轮的决定

1. **登记的有效期。** 一条记忆读过之后，怎样判断当前任务仍依赖它？Worker 进程退出或重启时，尚未完成的任务怎样恢复这部分依赖？
2. **读取与登记之间的空档。** 如果更正恰好发生在读到旧版之后、登记完成之前，怎样借助变更游标或版本复核补上这次通知？
3. **用户已经看见部分输出时的边界。** 普通草稿可以等到下一轮。流式回复若已展示旧时间，或工具请求正在等待渠道接单，应在什么时点暂停余下输出、核对回执并向用户更正？

Worker 的具体更新方式仍待讨论。可先用同一个会议案例分别比较“更正早于发送”和“更正晚于送达”，再决定哪些场景值得打断生成。

## 修订二　样板句在记忆工具返回中的作用

**项目方明确的定义。** 样板句是记忆工具的返回内容在送入或送出主模型（Master）或 Worker 时使用的自然语言包装，专用于承载这次工具返回的记忆。送入模型时，适配器用工具实际返回的数据填句。模型输出中需要继续传递这段记忆时，样板句保留其内容与来源。模型据此形成的判断、派给 Worker 的任务和面向用户的回复各用自己的正文表达。

**可由 SQL 解释**指句式有确定的含义，每个可变部分都能对应到记忆数据。会议改期用到的更正句可以写成“根据《来源》，《事项》已从《原值》改为《新值》。”执行层可以按这个句式识别一条更正，把需要核对的值绑定为 SQL 参数。反过来，从实际查询结果取出来源、事项、原值和新值，就能填出送给模型的那句话。这里的四项是句式表达的逻辑字段，具体表列和 SQL 模板由记忆适配器契约确定。

Java 实施稿第 1.2 节也用“样板”描述检索和写入请求。本草稿把发起操作的表达称为“检索请求”或“写入请求”，将“样板句”专指工具的记忆返回。按修订一的候选方案，注册表登记工具实际返回的记录标识和版本，即使两条记忆措辞相同，也能分别追踪其修订。[Java 实施方案第 1.2 至 1.4 节](master-worker-router-java-implementation-20261118.md)
