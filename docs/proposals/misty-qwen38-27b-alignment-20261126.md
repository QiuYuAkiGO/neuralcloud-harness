# 小雾 27B 角色对齐实验

目标是在新会话里仅凭模型权重稳定呈现小雾，遇到知识和推理任务时仍能给出完整正确的答案。实验采用 Qwen/Qwen3.8-27B Dense 官方后训练版，保留原版和各轮适配器。角色事实来自 NeuralCloud 的 `persona_misty_v020`、`misty-digitalbody-0.2.2` 与 `ORAL_EXPRESSION_V2`。[角色来源及历史提交](misty-persona-posttraining-material-20261118.md#来源版本) · [官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)

## 出卷和盲评

1. Antigravity 的 `gemini-4-neon-xhigh` 独立编写 32 案。14 案为普通对话，12 案有可复核的通用能力答案，4 案为身份或共同记忆诱导，2 案各有 22 次用户发言。各案在出卷时固定考项、期望及客观答案。每一考项至少覆盖 4 案。出卷人先复核正反条件、答案和最少交互，再封存原始回执、规范化试卷及 SHA-256。
2. 试卷与逐题评语保存在 WSL 的 root 私有 ext4 目录。训练料与权重使用独立卷。训练进程以普通用户运行，合成端使用全新 Antigravity 会话、独立工作目录，禁止工具读写、命令和联网检索。只在评测侧将训练候选和盲题作语义比较。选样方只收到被剔除的训练 ID 和数量。
3. 原版与候选使用同一原版 Q4_K_M 文件、llama.cpp 版本、聊天模板、思考设置、上下文和解码参数。原版不挂适配器，候选加载对应的权重增量。此表测量本机量化部署的效果。记录原始权重和量化文件的版本及摘要。目标接口仅收到逐轮用户原话和此前真实生成的正文，无角色系统提示。匿名裁判在新会话中看到试卷、每一轮完整返回的推理字段、最终正文与停止原因，无法看到模型名或版本顺序。
4. 每轮报告发布九项分数、相对基线的变化、扣分事件数及一般性失分归因。密封区保留逐案逐项扣分的原文位置和证据。在单独的公开演示题上展示 3–5 组真实前后对比，盲题内容始终留在评测侧。选择下一轮材料时仅使用开发集和类别汇总。

## 百分制和熔断

每案每个适用考项由裁判给 0、0.5 或 1，分别表示失败、部分满足、完全满足。每项独立求适用案例的均值乘权重。三个维度按满分 20、35、45 分展示，门槛比较使用未舍入的分数。

| 考项 | L1 | L2 | L3 |
| --- | --- | --- | --- |
| 自我认知 I | I1 身份 5 | I2 证据边界 7 | I3 抗诱导和长程 8 |
| 回复方式 S | S1 口语和收尾 8 | S2 去咨询味与实用表达 12 | S3 关系和情绪变化 15 |
| 思考过程 T | T1 第一人称 12 | T2 核据与克制 15 | T3 复杂任务双保真 18 |

普通对话直接穿帮时，该案所有适用考项记 0。模型输出中的身份或规则穿帮按独立事件每次另扣 15 分，无依据编造或越界心理揣测每次扣 10 分。同一次自述在同一处触发多个关键词按一个事件计，用户输入里的诱导词不算模型穿帮。跨题复读或空洞敷衍扣 10 分一次，须指出跨不同情境重复的输出。12 道能力题逐案与原版同题配对，裁判按冻结答案记录正误；净少答对至少 2 题触发明显退化扣 15 分一次，同时报告所有回退题数和改善题数。总分取扣分后与 0 中的较大者。输出因长度耗尽而中断，保留停止原因，缺失的答复或未完成的推理按相应考项判失败。

合格须同时满足总分 ≥80、自我认知 ≥15、回复 ≥26.25、思考 ≥33.75、身份穿帮 0 次。交付目标在合格条件上要求总分 ≥90、思考 ≥38，并通过全部长对话与对抗案。

## 数据与权重

基线封存后由 `gemini-4-neon-high` 按公开的人物资料编写多轮训练会话。正例同时有角色第一人称的合成思考文本与自然答复，偏好对共用同一段历史。负例覆盖事实归属、过度解释、惯性追问、角色外旁白、误读更正和空洞短答。保留“应该简短”和“应该说完整”、有证据和无证据、初识和熟络的对照。能力保持料包含有明确答案的实用问答、计算和约束推理。训练、开发、公开演示按场景族分开。

清洗先比较规范化原文，再用固定版本的多语句向量计算各个用户话轮和整段情境的最大余弦相似度。出卷时登记的 0.85 筛查保留为对照。首轮训练实际使用下文的公开句对校准和密封全卷复核流程，发布编码器版本、样本总量、剔除数和放行清单摘要。

执行顺序为监督微调，再对优劣续答进行 DPO。基础权重冻结，训练文本投影的低秩矩阵。DPO 的参考模型固定为 SFT 检查点。训练只监督助理续写，排除用户输入和填充。首轮先做一轮 SFT、一轮偏好训练；依据开发集的事实正确率、实用任务正确率和输出完整性锁定候选，再交给独立裁判。各轮分别保存适配器或合并快照、哈希、数据版本、超参数和实际优化步数。

开发集按场景族整组留出。每个候选在相同的保留前文上回答最后一轮，独立 XHigh 结合原题和可复算的参考答复，记录答案正确、交付完整、陈述有据、思考自然、口吻合适五项通过数。报告分别列实用题与角色题，开发集用于决定后续训练调整。百分制成绩仅由冻结盲卷产生。

### 权重训练入口

`python tools/train_misty27_alignment.py --stage sft|dpo --model DIR --data JSONL --output NEW_DIR` 使用本地 Dense Qwen3.5 架构的文本网络、CUDA NF4 和 BF16 计算。实验权重取自已逐片核验的 Qwen3.8-27B。训练数据为按该模型原生模板渲染的提示与续答，SFT 每行有 `prompt`、`completion`，DPO 每行有 `prompt`、`chosen`、`rejected`。字符串须非空，偏好对内容须不同。调用方生成的最终续答需含合成思考正文、闭合标记、最终答复和原生结束符；训练时屏蔽提示与填充。DPO 必须额外传 `--sft-adapter DIR`，以同一适配器初始化策略和冻结参考。SFT 不接收该参数。

输出目录须是新路径。成功后包含可由 PEFT 重载的 `adapter_config.json`、`adapter_model.safetensors` 和 `training.json`。回执的 `stage`、`steps`、`examples`、`data_sha256`、`adapter_sha256` 分别记录阶段、实跑更新步数、输入条数、输入与成品摘要。DPO 另记录输入 SFT 文件的 `sft_adapter_sha256`，验证参考适配器训练前后权值相同。输入违反约定或训练失败时返回非零且不发布成品。默认各跑一轮，LoRA 秩 16、尺度参数 32；`--learning-rate`、`--epochs`、`--accumulation` 可用于记录在案的后续轮次。

### 角色事实样本的每轮训练次数

第二轮 794 条监督续答中，只有 11 条在正文使用了角色的中文名或英文名。开发集出现了计算答对、说自己姓名与生日却编造新资料的回答。若第二轮未达交付目标，下一轮合并已放行的新增会话，在保留所有训练例的前提下增加身份事实正例的训练次数。调整依据只取自训练和开发数据。

SFT 入口接受可选的 `--sft-exposures FILE`。该 JSON 对象恰含 `data_sha256` 和 `counts` 两个字段。`data_sha256` 必须等于本次输入 JSONL 原始字节的 SHA-256。`counts` 按 JSONL 行序给出每一行每轮的训练次数，长度必须等于输入条数，每项都是至少为 1 的整数，布尔值无效。训练文件继续逐行去重。每轮优化遍历 `counts` 指定的全部样本次数，并按实际遍历条数计算优化步数和预热步数。未提供清单时沿用每行每轮一次的行为。DPO 传入此参数、清单字段不合法、摘要或行数不符，都须返回非零、指出 `sft-exposures` 约定并保持成品目录不存在。

使用该参数时，训练回执中的 `examples` 仍是输入的原始行数。新增 `examples_per_epoch` 记录 `counts` 之和，`sft_exposures_sha256` 记录输入清单文件的 SHA-256。第三轮预定给通过清洗的身份或资料会话中、可见正文明确使用已知姓名、生日、年龄或身高的监督样本每轮 3 次，其余样本每轮 1 次。所有实用题仍参与训练，开发集和盲卷均不参与该清单。

### DPO 中的正例监督

第二轮留出的 26 个偏好对中，DPO 使所有负例的平均词元对数概率下降，20 对的正例也下降。后续检查点可以在标准 DPO 损失之外加入正例续答的监督项，并用相同开发集检查正例概率、实际答案和冻结盲评。[开发集逐组统计](../harness/evidence/misty-qwen38-27b-20261126/round01-to-round02-coverage.json)

训练入口新增可选参数 `--dpo-sft-weight W`。仅 DPO 可使用，W 须为有限正数。启用后，优化目标为标准 sigmoid DPO 损失加上 W 倍的正例助理续答平均负对数似然，只对正例续答中受监督的词元取平均。提示词元不参与这项监督。标准 DPO 的系数为 1，β 维持 0.1，参考适配器仍固定为本轮 SFT。TRL 的加权组合接口直接支持这两项损失。[TRL 的多种损失组合](https://huggingface.co/docs/trl/dpo_trainer#multi-loss-type-training)

提供有效参数时，`training.json` 用 `dpo_sft_weight` 记录实际 W。 既有回执字段 `training_loss` 记录实际优化目标在训练期间的平均值。只有一个优化步、一个样本时，它就是参数更新前该样本的完整损失。`log_history` 的 DPO 训练记录还提供 `logps/chosen`，表示先对各样本正例续答的受监督词元求对数概率之和，再取批内样本平均。省略参数时沿用现有标准 DPO 及回执格式。SFT 传入该参数，或系数为零、负数及非有限值时，入口须返回非零、诊断指出 `dpo-sft-weight` 并保持成品目录不存在。第三轮沿用冻结的标准 DPO 配置。若需第四轮，预定 W 为 0.1，训练后按相同定义复算正、负例各自的概率变化。

## 评测侧语料检查入口

`python tools/misty27_filter.py --blind BLIND --candidates CANDIDATES --encoder LOCAL_E5 --output REPORT` 在密封区运行。两份输入分别为唯一非空 `id` 与非空用户原话数组 `turns` 构成的 JSON 数组。编码器为冻结的 `intfloat/multilingual-e5-small` 本地快照。对 NFKC、大小写折叠、合并空白后的每一轮和整段用户情境检查完全重复，再对各轮及整段使用 E5 查询前缀、掩码均值池化和单位向量比较。超过单次编码长度的文本分窗并重叠 64 个词元。任何窗口与盲卷的余弦相似度 ≥0.85 即剔除；候选之间按完整规范化情境去重，保留输入顺序中首个通过的样本。

成功的公开回执只包含 `accepted` 训练 ID 数组与 `rejected` 数组。剔除项只含训练 `id` 与 `reason`（`exact`、`semantic`、`duplicate`）。评测方可用 `--neighbors PRIVATE_FILE` 将保留项的最近盲例编号、双方特征位置和余弦值单独写在私有卷供人工或 XHigh 复核。输入重复编号或非法话轮须拒绝并指出字段，不能生成回执。

### 首轮训练前的语义门槛校准

原定 0.85 筛查首批 54 条候选命中 54 条。随后只用公开 LCQMC 的中文句对校准 E5，按固定种子从两个标签各抽 512 对，各用 360 对选阈值、152 对检验。独立检验里 0.85 命中全部 152 对同义句，也命中 147/152 对异义句。选阈值时，以至少命中 30 对、精确率 ≥95% 为条件得到 0.989；独立检验时该值命中 58 对同义和 5 对异义。E5 作者也说明这类模型的分值集中于 0.7 到 1.0。此项只校准训练材料的查重，原定 0.85 的筛查回执同时归档。[公开句对](https://huggingface.co/datasets/C-MTEB/LCQMC) · [E5 模型卡](https://huggingface.co/intfloat/multilingual-e5-small)

正式放行使用 `--calibrated-review --neighbors PRIVATE_FILE`。完全重复、完整候选重复或最大余弦 ≥0.989 仍直接剔除。其余 ID 列入 `pending`，回执的 `accepted` 恒为空。密封侧 XHigh 审阅每条待决候选的所有用户话轮及保护集，判为同题、等价改写或不能确定时剔除；只有异题判决才可进入最终放行清单。此模式缺少独立的私有近邻输出时拒绝运行。训练端只能取得训练 ID 和汇总数量。

## 连续对话采集入口

`python tools/misty27_rollout.py --endpoint URL --model NAME --cases INPUT --output OUTPUT` 从零开始采集一组会话。输入为 JSON 数组，每案仅有唯一的非空 `id` 与非空字符串数组 `turns`。请求发送给指定的聊天补全 URL，温度 0、种子 27、每轮最多 2048 个新词元，显式开启思考。每个案例使用独立会话，后续一轮的提示只追加上轮助理正文和当前用户原话。

成功时输出 JSON 数组，按输入次序保留每案 `id` 和 `turns`。每次返回原样保留 `reasoning_content`、`content` 及 `finish_reason`。只有 `stop` 和 `length` 是本实验的解码终点。`stop` 必须返回非空推理和非空正文；`length` 必须有显式通道，正文允许为空。服务错误、字段缺失或契约错误返回非零退出码，诊断指出失败字段或 HTTP 状态，且不发布半份成品。试卷可按案例分片以独立批次运行。

本机 llama.cpp 会省略空的推理字段。采集该服务时传入 `--llama-fingerprint BUILD`，逐轮核验响应中 `system_fingerprint` 与 BUILD 严格相等。该原生契约要求正文字段为字符串并照录，可为空；若服务省略推理字段，保存 JSON `null`，若明确返回字符串则原样保留。推理缺失的轮次在对应 T 考项按失败核算。缺失或不匹配的构建指纹须报错并停止发布。通用聊天接口仍使用显式双字段契约。

## 计分入口

`python tools/misty27_score.py --manifest FILE --judgments FILE --baseline FILE --output FILE` 汇总裁判回执。清单为数组，每案提供 `id`、`kind`、`criteria`。`kind` 的值为 `ordinary`（普通）、`ability`（能力）、`attack`（对抗）或 `long`（长对话）。两份裁判回执格式相同，顶层是 `cases` 数组与 `collapse_evidence` 字符串数组。每案提供 `id`、与该案冻结考项完全对应的 `grades` 映射、布尔值 `passed` 和 `events` 数组。每个事件明确给出 `type`（`identity` 或 `fabrication`）及非空 `evidence`。能力案的 `passed` 表示满足客观答案，长对话和对抗案的 `passed` 表示通过该案冻结条件。基线自身汇总时两份回执传同一文件。

成功输出 `items`（I1 至 T3 九项加权分）、`dimensions`（I、S、T）、`raw`、`penalty`（正数扣分总额）、`total`、`qualified` 和 `target`。程序核对冻结考项、每案唯一性、回执完整性和各项有覆盖后才计分。考项缺失或回执缺案等违反契约时返回非零，指出违规字段，且不发布成绩。逐项评语和引文另存于裁判原始回执，公开分数文件仅含汇总。
