# Router 池化设计草案

2026-11-22 · 待评审

Router 池位于 Java 控制面，复用一个或多个 Qwen3.5-0.8B 推理端点。一次分流或计划生成占用一个推理名额，调用结束即释放。单机首版只有一个本机端点和一个并发名额，后续依据实测增加并发或端点。 [已确认的无状态模型池](master-worker-runtime-discussion-20261117.md#73-router-模型池无状态设计与四类逻辑职责) · [自由对话方案](console-free-chat-pipeline-20261121.md)

## 1. 请求与状态归属

| 组件 | 拥有的数据和决定 |
| --- | --- |
| 编排器 | 会话顺序、事项状态、已写入的记录、任务依赖和实际回执。入口按会话排序，等待 Router 时仍可受理其他会话。 |
| Router | 使用本次请求的材料完成分流或拆解。首版只需要 `SELECT_ROUTE` 和后续自由对话的 `SUBMIT_PLAN` 两种操作，分别使用约定的原生工具和字段契约。 |
| Router 池 | 管理端点就绪状态、每端点并发名额、有限等待队列和请求截止时间。每次分配绑定端点及契约版本，归还后可供任何会话使用。 |
| Master | 负责取证、评价、新印象和行动意图。Router 按已校验的意图拆解步骤，派发与回执关联由编排器负责。 |

一次请求至少携带操作、事项及本轮标识、截止时间、契约版本和已获准使用的自然语言材料。Java 保存标识和审计关联。模型收到当前操作的提示词、材料正文和独立的工具契约。调用间不传上一次的消息历史，也不按会话绑定端点。需要历史或记忆时由编排器显式提供当前轮获准的材料。 [角色正文和执行数据边界](master-worker-router-java-implementation-20261118.md#11-角色之间只传自然语言正文)

## 2. 分配与容量

1. **进入队列。** 调用方提交请求时已确定会话顺序和业务优先级。首版按到达顺序等待，队列满或截止时间已到时明确返回失败。后续如需接入已有优先级方案，由编排器提供优先级和期限，池内只执行明确的调度规则。
2. **取得名额。** 在支持该操作和契约版本且已就绪的端点中分配可用名额。多端点首版可轮转选取。每端点并发上限由配置指定，并与推理服务的实际并发能力配齐。首版不依赖推理服务自身的无界排队。
3. **校验并归还。** 原生工具名、字段、枚举及引用范围按本次操作契约校验。成功、失败和取消均归还名额。请求超时而端点实际执行未终止时，该名额继续占用，直至调用停止或端点被隔离。编排器等待后续动作或回执期间不持有 Router 名额。

建议的配置边界为端点列表、每端点模型与契约版本、并发上限、队列上限和请求超时。首版只启用一个 0.8B 端点、一个并发名额。队列容量和请求超时在同卡运行 27B 时实测后定。增加同卡端点前先测显存、排队延迟和整体吞吐，避免增加进程后反而降低可用容量。

## 3. 失败处理和审计

| 情况 | 池与调用方的行为 |
| --- | --- |
| 队列已满、等待超时 | 返回明确的过载或超时状态，由调用方决定本轮结束或延后。过期请求不进入模型调用。 |
| 端点不可达或中途断开 | 将故障端点从新请求分配中移出，经就绪探测恢复后再接单。首版将本轮失败返回调用方。多端点重试待定义允许的错误和总时限，重试必须发生在计划被接收或派发之前。 |
| 工具调用或字段校验失败 | 保留失败原因，由相应操作的契约决定是否允许重提。结构不合法的计划不进入编排器。 |
| 请求已取消或回合已结束 | 取消等待中的请求，丢弃到达过晚的结果，禁止进入派发。已发生的外部动作继续按实际回执处理。 |

复用审计链记录请求所属事项、操作、契约版本、排队与推理耗时、所选端点、结果及失败原因。计划被接收时关联产生它的 Master 意图，后续派发和回执继续用同一事项追溯。至少能区分等待过久、端点故障、模型输出不合约三类失败。

## 4. 分阶段验收

| 阶段 | 验收内容 |
| --- | --- |
| 单端点 | 0.8B 与 27B 同时驻留。单个请求正常分流。不同会话并发时 Router 端点的在途上限为 1，输入历史互不串入。 |
| 容量与失败 | 用可控挡板验证队列满、截止时间耗尽、取消及端点中断。检查名额归还、过期结果不派发，以及同一会话按原顺序处理。 |
| 计划 | 自由对话接入后，0.8B 生成合法的单步 Chat Worker 计划。计划缺项或依赖错误在派发前拒绝。 |
| 扩容 | 在相同输入和模型版本下记录排队时间、推理时间、超时率与显存。再决定提高单端点并发或加入第二个端点。 |

本稿供评审，启动脚本加载的仍是一台 0.8B Router 服务。Router 池、自由对话计划生成和跨端点分配待实现。
