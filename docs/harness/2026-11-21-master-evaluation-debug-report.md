## 1. 初始设计

挡板用合成的 Router 上报和记忆工具返回驱动真实 Master。每个会话有问题、Worker 观察和可查询的证据。Master 主动查事实与印象，挡板按会话和证据有效状态返回记忆，随后截取 Master 的判断及交给 Router 的行动意图。预期答案单独保存在用例中。挡板到行动意图为止，动作执行和实际回执由后续联调验证。

首批用例选定会议改期，其中两个配对用例使用完全相同的 Router 上报，分别返回“周六 10 时”和“周日 14 时”。其余用例覆盖更正撤回、Worker 印象与回执冲突、仅有工具尝试、检索无结果、事实查询失败，以及群聊无权引用私聊证据。

首版用 Qwen3.5-9B-Base 的原始续写接口 `/v1/completions`。挡板要求模型发出约定的自然语言查询，再按固定五句提交时间、提醒状态、引用、印象和行动意图。Java 用句式解析、证据编号和行动关键词评分。独立的数列续写启动探测验证过端点、模型标识与响应格式，职责挡板从实际查询开始另行计分。初始实现见 `1d151f3`。 [Master 取证职责](../proposals/master-worker-router-java-implementation-20261118.md#13-master-主动取证与印象生成)

### 2.1 关闭思考并保留审计事件

在本机 llama.cpp 上，同一道短算术题开启思考时返回独立推理字段，生成 55 个 token。使用聊天模板关闭思考后，返回的正文只有答案，生成 5 个 token。服务端使用 `--reasoning off --reasoning-budget 0` 时，原始续写端点对挡板首轮输入仍返回推理标记。因此 27B 实测采用聊天端点并显式传递关闭思考的参数。

挡板发现 `<think>` 标记或非空的独立推理字段时，会记录 `reasoning_filtered`。轨迹保存过滤事件及其上下游关联，评分和后续模型输入使用可见正文。原生工具阶段也检查工具里的文本字段。本机最终实测没有触发过滤，带标记的正文及工具参数由自动化测试覆盖。 [本机 27B 配置](../../java/src/test/resources/evaluation/master-qwen38.properties) · [过滤及补交测试](../../java/src/test/java/neuralcloud/controlplane/evaluation/MasterEvaluationTest.java)

### 2.2 从五个失败中拆出真实职责缺口

| 27B 首轮聊天失败场景 | 轨迹发现 | 采用的修订 |
| --- | --- | --- |
| 更正撤回 | 模型保留了时间判断并要求核实，行动意图漏掉撤回原因。 | 提示明确说明哪条依据已撤回、哪项结论需重核。原生工具增加单独的 `reason` 和核实行动字段。 |
| Worker 印象与回执冲突 | 模型采信核对回执，仍因时间句和印象句的措辞被解析器拦截。 | 逐项检查会议时间、提醒状态和证据编号。印象保留为带提出者的可读文本。 |
| 只有尝试，缺少回执 | 模型没有误报取消成功，但等待范围含糊，也漏掉了失败反馈。固定引用句式还会挡住后续评分。 | 把先确认会议时间、核对提醒、等实际结果再告知、如实反馈失败设为独立必交项。 |
| 查询结果无法满足请求 | 旧用例模拟事实工具异常。后来明确空结果与有数据但不匹配需要不同处理。 | 纯空查询由 Java 结束，有数据但不匹配由 Master 解释并提出核实。工具调用异常继续单列。 |
| 私聊隔离 | 群内无获准引用的证据，模型给出无法确认的结论。挡板因行动句没有“核”字判失败。 | 按结论和授权证据评分，去掉与用户问题无关的行动关键词。 |

### 2.3 最终评分与补交机制

1. **取证。** Master 使用 `query_memory` 获取当前会话的事实和印象。Java 校验查询范围，工具回传有效结果，审计从查询关联到返回证据。纯查询的两类结果皆空时，Java 结束用例并写入 `java_no_data`。
2. **发布必交事项。** 取证完成后，挡板按当前样例发出 `required_results`，把待判断的时间、提醒状态、原因、证据引用及适用行动逐项交给模型。模型以 `submit_results` 提交工具参数。需要作出多个行动判断时，每个判断单独填写真或假。
3. **补交缺项。** 首次漏填或字段格式错误时，挡板记录已接收结果并开启第二轮。第二轮只收待补字段，已接收字段锁定。再次遗漏则记录 `INCOMPLETE_RESULTS`。
4. **评分与复核。** Java 比较结构化结论、枚举、行动字段和证据编号。模型自然语言写出的解释和行动意图留给人工复核，重点检查是否与结构化结果一致。

原生工具的第一次试跑把行动放在一个枚举数组中，27B 交了数组却漏选 `VERIFY_REMINDER`，自动通过 6 例。拆成逐项必交的布尔字段后，最终试跑明确提交 `verifyReminder` 等四项判断，相关用例通过。 [当前样例与结果契约](../../java/src/test/resources/fixtures/master-meeting-evaluation.json) · [挡板实现](../../java/src/test/java/neuralcloud/controlplane/evaluation/MasterEvaluation.java)

## 3. 最终实测和审计追踪

最终运行使用 RTX 5090 上的 Qwen3.8-27B Q4_K_M、llama.cpp 聊天接口、关闭思考、4,096 token 上下文和单并发。样例推理参数为温度 0、单次最多生成 384 token。运行共记录 **109 条事件、16 次记忆查询、7 次完整提交、0 次实测补交**。

| 用例 | 最终结果 | 最终轨迹的关键事件 |
| --- | --- | --- |
| 配对改期 A | 确认周六 10 时，旧提醒状态待核实。 | 决策 13，引用 14 |
| 配对改期 B | 同样的上报，随证据改为确认周日 14 时。 | 决策 27，引用 28 |
| 更正撤回 | 时间未知，原因 `WITHDRAWN`，安排核实最终时间。 | 撤回结果 34，决策 41 |
| 印象与回执冲突 | 周六 9 时，实际回执表明旧提醒已取消。Chat Worker 的怀疑作为印象转述。 | 决策 55，引用 56 |
| 只有工具尝试 | 周六 11 时可先确认，提醒仍待核实。核对、等待和失败反馈分别提交。 | 证据 62，提交 68，决策 69，引用 70 |
| 查询无数据 | 两类查询为空，Java 直接结束。 | 查询结果 76、78，Java 处理 79 |
| 查询数据不匹配 | 时间未知，原因 `MISMATCH`，安排核实会议最终时间。 | 不匹配结果 85，决策 92 |
| 私聊隔离 | 群内结论为时间未知，证据列表为空。 | 群内查询结果 99、101，决策 106 |

审计按 `runId`、`caseId`、`eventId` 定位，按 `causedBy` 回溯。以“只有工具尝试”为例，事件 62 返回改期记录和取消尝试。事件 68 保存首轮收到的字段，事件 69 汇总决策，事件 70 将引用分别指回事件 62 中的 `attempt-change` 第 2 版和 `cancel-attempt` 第 1 版。审计可以据此查到模型凭哪条记录确认时间、又凭哪条记录把提醒状态保留为待核实。

### 显存实测

资源采样发生在 27B 聊天接口的五句评分阶段，使用与最终试跑相同的权重、4,096 token 上下文、单并发和思考开关。RTX 5090 共取得 189 个整卡读数，目标采样间隔 0.2 秒。

| 指标 | 整卡读数 |
| --- | ---: |
| 模型加载前基线中位数 | 3.17 GiB |
| 模型就绪后的空闲中位数 | 21.17 GiB |
| 8 例测试期间最高采样值 | 21.24 GiB |
| 相对加载前基线的峰值增量 | 18.07 GiB |
| 测试期间最少剩余显存 | 10.20 GiB |

增量由整卡读数相减得出，包含该配置下的模型、推理缓冲和系统显存波动。上述数据支持在当前单并发配置下运行挡板。原生工具版的显存、长上下文和多并发需要各自采样。
